# ร่าง tickets: OCR Playground

ตัวเลขใน Blocked by อ้างถึง ticket ในเอกสารนี้ และจะเปลี่ยนเป็น GitHub issue หลังอนุมัติ

## 1. ออกแบบประสบการณ์ OCR และเริ่มอัปโหลดงาน
**Blocked by:** ไม่มี

**What to build:** ออกแบบด้วย impeccable และสร้างหน้า Next.js responsive ภาษาไทยที่เลือก JPG, PNG หรือ PDF และส่งสร้างงานผ่าน BFF ไปยัง backend fixture ได้

**Acceptance criteria:**
- [ ] UI ใช้ keyboard และมือถือได้ และแจ้งไฟล์ที่ไม่รองรับหรือ backend ปฏิเสธ
- [ ] ส่ง multipart ผ่าน BFF และแสดงผลเมื่อรับ job ID หรือการส่งไม่แน่นอนโดยไม่ retry อัตโนมัติ
- [ ] มี automated test ผ่าน browser และ backend fixture

## 2. แสดงความคืบหน้าจนงานสิ้นสุด
**Blocked by:** 1

**What to build:** ผู้ใช้เห็น queued, processing และความคืบหน้าของหน้าที่ประมวลผลแล้ว รวมถึงสถานะสำเร็จ ล้มเหลว และสำเร็จบางส่วน

**Acceptance criteria:**
- [ ] Poll จนสถานะสิ้นสุดและหยุด จากนั้นแสดงผลที่ตรงกับสถานะ
- [ ] จัดการ network error และ job หมดอายุอย่างชัดเจน
- [ ] ผล request เก่าไม่เปลี่ยน session งานใหม่

## 3. ดูและแก้ไขผล OCR รายหน้า
**Blocked by:** 2

**What to build:** ผู้ใช้เลือกหน้า ดูภาพคู่ข้อความ แก้ไข คัดลอก และยืนยันคืนค่าต้นฉบับได้

**Acceptance criteria:**
- [ ] สลับหน้าแล้วเก็บ draft รวมข้อความที่ตั้งใจแก้เป็นค่าว่าง
- [ ] หน้าว่างที่สำเร็จแก้ไขได้ และหน้าล้มเหลวแสดง error แยกกัน
- [ ] ภาพ binary ผ่าน BFF; layout ใช้งานได้บนมือถือและ desktop

## 4. ดาวน์โหลดผล OCR และข้อความที่แก้
**Blocked by:** 3

**What to build:** ผู้ใช้ดาวน์โหลด TXT หรือ JSON สำหรับทุกหน้า รวมหน้าที่ไม่เคยเปิด

**Acceptance criteria:**
- [ ] TXT มีเลขทุกหน้าและระบุหน้าล้มเหลว; JSON แยกข้อความแก้จากผล OCR ต้นฉบับ
- [ ] เตือนก่อนดาวน์โหลดผลบางส่วนและไม่สร้างไฟล์เมื่อดึงหน้าที่สำเร็จไม่ครบ
- [ ] การแก้หลังดาวน์โหลดถือเป็นการแก้ใหม่ที่ยังไม่ได้ดาวน์โหลด

## 5. ปกป้องข้อความและจัดการจบงาน
**Blocked by:** 4

**What to build:** ผู้ใช้จบหรือเริ่มงานใหม่พร้อมจัดการข้อความที่แก้และข้อมูลชั่วคราวได้

**Acceptance criteria:**
- [ ] ยืนยันก่อนทิ้งข้อความที่ยังไม่ได้ดาวน์โหลด และเตือนเมื่อออกจากหน้าเท่าที่ browser รองรับ
- [ ] ส่ง DELETE; เมื่อผิดพลาดให้ลองใหม่หรือเริ่มใหม่ต่อได้ พร้อมแจ้งการหมดอายุเป็นกลไกสำรอง
- [ ] เมื่องานหมดอายุ ผู้ใช้คัดลอก draft ในหน่วยความจำได้ก่อนเริ่มใหม่ และไม่สร้าง export ที่อาจไม่ครบ
- [ ] เตือนอีกครั้งเมื่อมีการแก้ไขหลังดาวน์โหลด

## 6. ตรวจ workflow กับ backend จริง
**Blocked by:** 2, 4, 5 และ backend API ที่ตกลงพร้อมใช้งาน (ภายนอกชุด tickets นี้)

**What to build:** ตรวจการใช้งานจริงตั้งแต่อัปโหลดจนลบงานกับ backend และปรับ contract ที่ต่างจาก fixture

**Acceptance criteria:**
- [ ] ยืนยันสถานะ, error, schema, file/page limits, expiry และการลบข้อมูลกับ backend
- [ ] ทดสอบไฟล์หลายหน้า ภาพ พิกัด multipart และ failure cases ผ่าน BFF จริง
- [ ] บันทึกข้อจำกัดที่ยังเปิดอยู่และผลตรวจ end-to-end
