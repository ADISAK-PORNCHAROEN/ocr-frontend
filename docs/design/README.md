## แบบ A — Quiet Studio

[เปิดต้นแบบ](concept-a.html) · [ภาพตัวอย่าง desktop](concept-a-desktop.png) · [ภาพตัวอย่าง mobile](concept-a-mobile.png)

บรรยากาศสว่างและอบอุ่น เน้นพื้นที่เทียบเอกสารกับข้อความ ใช้สีเขียวเป็นจุดเน้น เหมาะกับการอ่านข้อความต่อเนื่องเป็นเวลานาน ข้อแลกเปลี่ยนคือบุคลิกจะสงบกว่าอีกสองแบบ

- รูปแบบ: แถบด้านบนสีเขียวเข้ม, พื้นครีม, tab เลือกหน้า และพื้นที่ภาพ/ข้อความสองฝั่ง
- สีต้นแบบ: พื้น `#f4f1e9`, สีหลัก `#173f35`, พื้นเอกสาร `#fffdf8`; จับคู่ตัวอักษรไทย sans กับหัวเรื่องแนวหนังสือ
- พื้นที่บนมือถือ: เรียงภาพก่อนข้อความ และให้แถบหน้าเลื่อนเมื่อพื้นที่ไม่พอ

## แบบ B — Signal Desk

[เปิดต้นแบบ](concept-b.html) · [ภาพตัวอย่าง desktop](concept-b-desktop.png) · [ภาพตัวอย่าง mobile](concept-b-mobile.png)

กรอบงานสีเข้มช่วยแบ่งพื้นที่และให้บริเวณเอกสารกับ editor สว่างเด่น เหมาะกับ portfolio ที่ต้องการภาพจำชัดเจน ข้อแลกเปลี่ยนคือต้องตรวจ contrast และการจัดการพื้นที่บนมือถืออย่างละเอียด

- รูปแบบ: แถบนำทางสีกรม, พื้นที่ทำงานสว่าง, แถบความคืบหน้า และปุ่มส่งออกที่เห็นได้ชัด
- สีต้นแบบ: พื้น `#f1f5f9` กับแถบสีกรมและสีฟ้าสำหรับการกระทำหลัก; ใช้ตัวอักษรไทย sans
- พื้นที่บนมือถือ: ปรับแถบนำทางเป็นแนวนอนและเรียงพื้นที่อ่านเอกสารกับ editor

## แบบ C — Paperflow

[เปิดต้นแบบ](concept-c.html) · [ภาพตัวอย่าง desktop](concept-c-desktop.png) · [ภาพตัวอย่าง mobile](concept-c-mobile.png)

โทนสว่างอมม่วงและการนำทางรายหน้าในแนวนอน เน้นให้เห็นลำดับงานและเอกสารหลายหน้า ข้อแลกเปลี่ยนคือแถบหน้าต้องปรับขนาดและเลื่อนได้ดีเมื่อมี PDF หลายหน้า

- รูปแบบ: หน้ารับไฟล์นำด้วยขั้นตอนการใช้งาน ตามด้วยตัวอย่าง workspace และแถบ thumbnail รายหน้า
- สีต้นแบบ: พื้น `#f1f2fa`, สีหลัก `#385e98`, พื้นเอกสาร `#fffefb`; ใช้ตัวอักษรไทย sans
- พื้นที่บนมือถือ: เรียงส่วนรับไฟล์และ workspace ในแนวตั้ง พร้อมคงลำดับขั้นตอนให้อ่านได้

แบบ C เป็นแนวทางที่เลือก สีและฟอนต์ปัจจุบันอยู่ใน CSS ของแอป ภาพ implementation แสดงงาน OCR สังเคราะห์สองหน้าที่ความกว้าง 1440px และ 390px; browser tests ตรวจการจัดวางมือถือและ keyboard flow

## พฤติกรรมที่ทุกแบบต้องรักษา

- หน้าแรกอัปโหลด JPG, PNG หรือ PDF หนึ่งไฟล์ได้ทันที และแสดงข้อผิดพลาดกับความคืบหน้าอย่างเข้าใจได้
- แสดงภาพคู่ข้อความบน desktop และเรียงให้ใช้งานได้บนมือถือ หลังงานเข้าสู่สถานะสิ้นสุด
- แยกหน้าว่างที่สำเร็จออกจากหน้าล้มเหลว เก็บข้อความที่แก้ใน session และยืนยันก่อนคืนค่า
- ให้คัดลอกและดาวน์โหลด TXT/JSON โดยเตือนเมื่อผลไม่ครบ และไม่สร้างไฟล์เมื่อดึงหน้าสำเร็จมาไม่ครบ
- แจ้งเมื่อข้อมูลหมดอายุ อนุญาตให้คัดลอกข้อความที่ยังอยู่ และยืนยันก่อนทิ้งการแก้ไขที่ยังไม่ได้ดาวน์โหลด
- ตัวเลขขนาดไฟล์ จำนวนหน้าสูงสุด อายุข้อมูล และความสามารถ OCR ในต้นแบบไม่ใช่ข้อเท็จจริงจนกว่า backend จะยืนยัน

## Direction contract

**THESIS.** OCR Playground ให้ผู้ใช้เริ่มจากเอกสารและตรวจผลเป็นรายหน้า แทนการเปิดหน้า dashboard ก่อนเริ่มงาน.

**OWN-WORLD.** ใช้พื้น lavender `#f1f2fa`, แผงสีขาว, สี action `#385e98`, เอกสารสี `#fffefb`, เส้นขอบอ่อน และ UI ภาษาไทยที่อ่านง่าย.

**STORY.** ผู้ใช้เลือกไฟล์หนึ่งไฟล์ เห็นสถานะงาน แล้วตรวจภาพและแก้ข้อความของหน้าเดียวกัน ก่อนดาวน์โหลดผลหรือจบงาน.

**FIRST VIEWPORT.** ใช้ shell กว้างสุด 1440px บน desktop วางแถบชื่อโปรเจกต์ด้านบน ตามด้วยหัวข้อและคำอธิบาย แถบสามขั้นตอน และแผงรับไฟล์สองคอลัมน์. Workspace ใช้คอลัมน์ภาพและ editor ขนาดเท่ากัน. ที่ 780px ให้เรียงแนวตั้ง และที่ 520px ใช้ขอบด้านข้าง 14px.

**FORM.** ใช้แบบ C ตัวเลือกที่สามจาก A/B/C โดยวางพื้นที่รับไฟล์ก่อน workspace. `seed: none (pinned)` เพราะผู้ใช้เลือกคำว่า “Paperflow (concept C)”.

**FINISH.** unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
